# 评测方法论

## 一、为什么把评测"拆层"

最初 66 条检索集、48 条拒答集、60 条工具路由集**同时承担调参和对外报告**两个角色——
权重网格搜索、阈值标定、bad case 修复都在这些集合上完成，再把分数当"泛化能力"。
这是循环论证。拆成三层后，每个集合只有一个职责：

| 层 | 用途 | 参与调参 | 对外报告 |
|---|---|---|---|
| **dev** | 调参、找 bad case、CI 回归 | ✅ | ❌ |
| **holdout** | 对外报告的唯一依据（先冻结、后测试） | ❌ | ✅ |
| **regression** | 防回退护栏（断言不低于阈值） | ✅（历史） | ❌ |

## 二、数据集构成

| 数据集 | 规模 | 设计要点 |
|---|---|---|
| v1 简单集 | 110 条 | 题面照抄文档标题，**只作回归护栏**（任何 embedding 都能满分） |
| v2 困难集 | 66 条 | 口语化提问、不含标题关键词，用于真实检索评估 |
| 拒答平衡集 | 48 条 | 24 应拒 + 24 应答；避免"全部拒答即满分" |
| 工具路由集 | 60 条 | 覆盖 10 工具、6 城市、5 多跳、12 易混淆边界 |
| 端到端集 | 24 用例 | 8 政策 / 10 数据 / 6 超纲，含引用与拒答一致性 |

## 三、指标定义

| 指标 | 定义 |
|---|---|
| Recall@k | 期望文档 `source_id` 是否出现在前 k 个结果中 |
| MRR | 首次命中排名的倒数均值 |
| 拒答准确率 | 拒答判定与标注一致的比例，并拆分"应拒命中 / 应答正确" |
| 工具路由正确率 | 实际工具集合与期望集合**完全相等**（多一个也算错） |
| 引用正确率 | 回答中的引用是否来自工具结果 |
| 幻觉引用 | 引用了知识库中不存在的条款/标准号 |

## 四、评测抓出的三个真实缺陷

### 1. 同义反复：题面包含标题

v1 中 100% 的 query 原样包含目标文档标题，而打分公式里标题精确匹配权重 0.60——
等于把答案直接写进题面，任何 embedding 都拿 Recall@1 = 1.000。

### 2. 拒答是白名单

原拒答逻辑是硬编码 17 个词，与检索分数无关；44 条拒答样本全是负样本，"永远拒答"即满分。
改为基于原始余弦的阈值判定 + 平衡集后，指标才有意义。

### 3. 权重过拟合

旧权重（标题 0.60 / 关键词 0.25 / 向量 0.15）在 v1 上调出，语义信号只占 0.15，
在口语化提问上 Recall@1 损失约 30 个百分点。重新网格搜索后：向量 0.70 / 关键词 0.10 / 标题 0.10 / RRF 0.02。

## 五、阈值标定

- 用原始余弦（不是混合分）作为拒答置信度；
- 在 48 条平衡集上扫描阈值，选"应拒命中"与"应答正确"的平衡点；
- 最终取区间中点 0.53，而不是样本内最优值——对语料/分块变化更稳健；
- 所有阈值都记录在配置注释里，并写明"语料变更必须重新标定"。

## 六、冻结机制

holdout 的价值来自"先冻结、后测试"：

1. 独立出题（不看 dev 集）；
2. `freeze_holdout.py` 写入文件的 sha256；
3. 评测前校验，hash 不匹配直接拒绝运行；
4. 确需修改则升版本号并留痕。

> 这套机制的目的很直接：**防止包括自己在内的任何人"改测试集把分刷高"。**

## 七、可复现性

| 方式 | 依赖 | 用途 |
|---|---|---|
| 离线 hash 基线 | NumPy | CI 回归护栏 |
| BGE 向量缓存回放 | NumPy | 免 torch 复现语义指标；带语料 sha256 校验 |
| BGE 实跑 | torch | 首次生成缓存 |

评测产物（报告 JSON / Markdown 摘要）由 CI 上传为 artifact，可追溯到具体 commit。
