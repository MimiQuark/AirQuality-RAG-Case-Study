# 结果与边界

> 所有数字都来自仓库内脚本的真实运行。这里刻意把"口径"写清楚——**一个没有边界的数字，
> 在面试里是负资产。**

## 一、检索与拒答（v2 困难集，结构分块，chunk_size=400）

| 指标 | 离线 hash（CI 基线） | BGE-small-zh-v1.5（语义路径） |
|---|---:|---:|
| Recall@1 | 0.500 | **0.773** |
| Recall@5 | 0.848 | **0.985** |
| MRR | 0.633 | **0.862** |
| 拒答准确率 | 0.562 | **0.896** |
| └ 应拒命中率 | 0.458 | **0.958** |
| └ 应答正确率 | 0.667 | 0.833 |

**口径说明**

- 这是 **dev 集**结果（权重与阈值在它上面标定过），不代表泛化能力；
- hash 基线只用于 CI 护栏，不代表线上能力；
- 对外能力结论以独立 **holdout 集**为准（审校后公布）。

## 四、诚实的负结果

- **并发优化只有 1.18–1.20×**：工具是 CPU 密集型，受 GIL 限制；换进程池会重复加载数据，反而更慢；
- **分块策略提升不显著**：配对 bootstrap（4000 次）95% 置信区间跨零，所以选择依据是
  "不切断条款"的结构正确性，不是指标最优；（该 bootstrap 脚本未随仓库保留，结论仅作历史记录）
- **LLM 版引用不可信**：自由文本引用出现 3/18 幻觉，因此对外结论只认代码结构化提取的引用。

## 五、我们刻意不宣称的东西

| 不宣称 | 原因 |
|---|---|
| "LLM Agent 端到端准确率 91.7%" | 单次运行、样本 24、模型会更新，不可复现 |
| "本轮 Recall@1 提升显著" | bootstrap 不显著 |
| "生产可用" | 内存索引、SQLite trace、单机部署，都是演示级 |
| "100% 工具路由" | 是回归集，不是泛化 |
