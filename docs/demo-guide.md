# 演示与录屏脚本

> 私有代码方案下，**视频和文档就是你的"可运行证明"**。按这个脚本录两段，足够撑起一次技术面。

## 一、Demo 视频（5–8 分钟）

| 时间 | 画面 | 台词要点 |
|---|---|---|
| 0:00–0:40 | 仪表盘首页 | 项目一句话定位：10 个工具 + 政策 RAG + 可降级 Agent |
| 0:40–2:00 | 提问"北京现在的空气质量怎么样" | 展示工具选择 → 数据卡片 → 回答结构 |
| 2:00–3:20 | 提问"PM2.5 的国家标准限值是多少" | 展示检索 → 引用条款编号 → 来源链接 |
| 3:20–4:20 | 提问"个人所得税怎么申报" | 展示**拒答**：低置信度 → 不编造 → 引导回领域 |
| 4:20–5:30 | 提问"未来 24 小时会不会超标" | 展示预测工具 + 告警阈值 |
| 5:30–6:30 | 断网/去掉 API Key | 展示**规则 Agent 自动降级**，系统仍可用 |
| 6:30–7:30 | 跑评测命令 | 终端输出 Recall/拒答指标，说明"这是可复现的" |

**录制要点**：1080p、鼠标高亮、终端字号调大、不要出现任何密钥/私人路径。

## 二、代码走读（3 分钟，面试现场或录屏）

按这个顺序讲，每段 40 秒：

1. **检索打分**：打开 `rag/service.py`，讲向量 0.70 / 词法 0.10 / 标题 0.10 / RRF 0.02，
   以及"标题权重 0.60 会让评测满分"的教训；
2. **拒答**：讲为什么用原始余弦而不是混合分，阈值怎么扫描、为什么取区间中点；
3. **评测**：打开评测脚本，讲 dev/holdout 分层与冻结锁，"先冻结后测试"防刷分；
4. **缺陷修复**：讲案例 3（阈值随语料漂移）——这是最能体现工程判断的一段。
