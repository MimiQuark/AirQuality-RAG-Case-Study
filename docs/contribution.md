# 我在这个项目里做了什么

这是个大创项目，团队五个人：ChenT 管集成部署，我（ZhuY）做 RAG 和评测，ChenH 做 Agent 与工具层，LiangK 做数据与预测，WuS 做产品和用户研究。

写这份东西的原因很简单：这是个五人项目，但仓库一直由我统一提交，提交记录里只有我一个账号。不写清楚，别人容易误以为代码全是我一个人写的。所以下面主要说两件事——哪些是我做的，哪些不是。

## 我负责的部分

知识库是我建的，schema 怎么设计、来源字段怎么留、版本怎么管，都在我这。

检索这块包括打分公式（向量、词法、标题、RRF 融合）、权重搜索，还有结构分块的 A/B 对比。

拒答一开始用的是关键词白名单，后来发现指标恒为 1.000，才改成余弦阈值加平衡集。引用部分做了溯源和幻觉检测。

评测是我花时间最多的地方：把 v1、v2、拒答、路由、端到端五套评测重新搭起来，再拆成 dev 和 holdout，加了冻结锁。CI 也归我管。

具体落在哪些文件，看 `backend/rag/` 和 `backend/evaluation/` 就行。

## 不是我做的部分

Agent 编排和工具层是 ChenH 写的。`backend/agents/` 和 `backend/tools/` 里的 LangGraph 图、十个工具、规则降级，都不是我做的。

`backend/engine.py` 和 `backend/realtime.py` 是 LiangK 的，包括数据采集清洗、随机森林预测和告警分析。

前端和产品部分归 WuS，`static/` 下的仪表盘、问卷、竞品分析和可用性测试都算他那边。

FastAPI 接入、Docker 和 release 是 ChenT 负责的。

这些模块我熟悉接口，也参与过联调，但不会在面试里说成是自己写的。

## 关于 AI

项目最初的脚手架是 AI 辅助生成的，后面不少业务代码也有 AI 参与。我自己主要做的是评测、检索调优、拒答阈值标定、知识库和工程化这几块。

我觉得没必要回避这件事。现在写代码多少都会用 AI，问题不在用不用，而在于用完之后能不能讲清楚：为什么这么写、改了什么、怎么验证的。

## 三个我自己发现并修掉的问题

### 1. 两条检索路径返回的分块不一样

有一次调接口，发现 `/api/rag/search` 和 Agent 走的检索结果对不上。查了半天，最后发现是服务构造的时候漏传了 `chunk_strategy`，两条路径用的策略不一样。补上参数之后结果就一致了，回归指标没有变化。

### 2. 拒答指标一直是 1.000

三项拒答指标，不管换什么 embedding 都是 1.000，这明显不对劲。后来看样本才发现，全是负样本，代码里还有一个硬编码的白名单在提前拦截。重做了平衡集，改成余弦阈值，拒答准确率从 0.562 升到 0.896。

### 3. 知识库扩容后阈值失效

知识库从几十条扩到几百条之后，拒答从 0.958 掉到 0.771。查下来是可行阈值区间从 (0.409, 0.537) 漂到了 (0.489, 0.567)，原来定的 0.53 刚好掉出去了。重新标定到 0.53，并且把"语料一变就要重标定"写进了流程。
